Install

Download a release binary (linux / darwin / windows, amd64 + arm64):

curl -sL https://github.com/Blackman99/failshut/releases/download/v0.1.0/failshut_0.1.0_linux_amd64.tar.gz | tar xz
./failshut version

Or with Go 1.24+:

go install github.com/Blackman99/failshut/cmd/failshut@latest

Usage

failshut                 # audit (default)
failshut audit           # same
failshut audit --json
failshut audit --project /path/to/repo
failshut audit --rule ask-vs-effective
failshut mcp             # read-only MCP stdio
failshut version

Exit 1 if any FAIL OPEN finding; 0 if all fail shut or nothing is configured.

Colors when stdout is a TTY. Disable with --no-color or NO_COLOR=1.

What gets scanned

  • Claude Code: ~/.claude/settings.json, settings.local.json, project .claude/settings.json — hooks, permissionMode, allow/deny/ask
  • Codex: ~/.codex/config.toml (+ sibling *.toml) — approval_policy, sandbox_mode, sandbox_approval, profiles, delegation
  • OpenCode: opencode.json / .opencode/ under --project and user config dirs — permission deny/ask, path fields
  • Cursor: best-effort readable CLI permission files when present

Missing files are skipped. failshut never writes to your configs.

Rule IDs

  • deny-ignored — deny on read/grep/glob-like tools known to be ignored by harness quirks (opencode#55728 shape)
  • ask-vs-effective — Ask / approval_policy vs sandbox_approval=false or require_escalated + disabled sandbox (codex#54298 / #54440)
  • hook-missing — hook/plugin path referenced but missing or not executable
  • path-traversal-config — .. segment in project/session path that can load a sibling opencode.json (opencode#55909)
  • delegation-escalate — plan/read-only or restrictive profile can spawn a general/write subagent without the same profile (opencode#55814, codex#54448)
  • ask-auto-allow — hooks / permissionMode ask paired with desktop auto-allow (claude-code#102582)

FAQ

Does this block tools at runtime? No. v0.1 is a static auditor. Live canaries are on the roadmap (--canary returns “not in v0.1”).

Nothing configured — is that fail-open? No. Clear message, exit 0. You still need policies for policies to hold.

MCP? failshut mcp exposes read-only tools audit_report and list_findings. It never mutates configs.

False positives? Rules mirror public issue shapes. Open an issue with a redacted fixture if a sealed config flags.
