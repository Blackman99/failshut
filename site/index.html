Config says DENY. Runtime says ALLOW? Pressurize the manifold.

One command tells you whether Claude Code / Codex / OpenCode permission hooks and deny/ask rules actually fail shut — or silently fail open.

curl -sL https://github.com/Blackman99/failshut/releases/latest/download/failshut_Linux_x86_64.tar.gz | tar xz
./failshut audit

or go install github.com/Blackman99/failshut/cmd/failshut@latest

What bubbles mean

FAIL OPEN

A deny/ask/hook is configured in a shape the harness is known to ignore — or Ask is paired with an auto-approve override. Exit code 1.

FAIL SHUT

Scanned configs look sealed for the static rules we ship. Exit code 0. (Nothing configured also exits 0 — with a clear message.)

Six static leak points

  • deny-ignored — deny on read/grep-like tools the harness may skip
  • ask-vs-effective — UI Ask vs sandbox_approval=false / silent escalate
  • hook-missing — referenced hook path missing or not executable
  • path-traversal-config — .. in project path can load a sibling config
  • delegation-escalate — plan/restrictive profile spawns a general subagent
  • ask-auto-allow — hook asks, desktop auto-allows

v0.1 is a static auditor. It does not intercept live tool calls. See docs.
